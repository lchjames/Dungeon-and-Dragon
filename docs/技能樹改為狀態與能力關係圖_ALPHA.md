# 技能樹改為狀態與能力關係圖 — Alpha

> 狀態：Canonical Alpha Override  
> 範圍：玩家技能樹、能力取得、技能點、能力前置、世界內學習來源、角色能力狀態顯示。  
> 本文件覆蓋任何較早規格中「玩家可以直接在技能樹節點消耗技能點並自動學會火球術／劍技／其他具名能力」的描述。

---

## 1. 核心方向

技能樹不再是「購買／解鎖能力」的介面。

Canonical：

```text
技能樹／能力圖譜
=
角色目前能力狀態 + 能力之間的關係／前置／來源提示
```

它不是：

```text
升級
↓
節點亮起
↓
按一下
↓
自動學會火球術
```

角色要真正取得一個能力，必須透過遊戲世界內的取得來源，或由 GM 授予。

---

## 2. 角色能力不能因升級而自動出現

角色的等級、屬性階級或技能值提高，只代表：

- 角色可能達到某些能力的使用條件；
- 角色可能有資格學習更高階能力；
- 某些已取得但不可使用的能力可能變成可使用。

它不代表角色自動學會任何具名能力。

例如：

```text
火屬性階級：一階
角色已學：火球術
```

日後火屬性升到二階：

```text
火屬性階級：二階
```

不會自動得到：

```text
強化火球
炎爆術
火焰牆
```

角色仍然需要在世界中取得／學習這些能力。

---

## 3. 能力取得應來自世界，而不是技能樹

典型來源包括：

```text
導師
師傅
學校／學院／門派
訓練機構
卷軸
秘籍／書本
特殊物品
商店
任務獎勵
劇情事件
職業／身份授予
血統／覺醒
GM直接授予
其他世界內來源
```

其中：

### 玩家可自行完成的來源

例如：

```text
商店購買
使用卷軸
閱讀／使用符合規則的秘籍或物品
其他已由 GM 預先設定並可由系統驗證的取得方式
```

玩家完成條件後，系統可以直接將能力標記為「已取得」。

### GM／劇情控制的來源

例如：

```text
導師教授
師傅傳授
學校畢業／課程完成
門派傳承
任務／劇情獎勵
覺醒
特殊事件
GM直接授予
```

機械上可由 GM 授予能力，並記錄其世界內來源。

---

## 4. 技能樹只顯示能力狀態

每個能力節點至少可顯示：

```text
未取得
已取得・不可使用
已取得・可使用
常駐能力／常駐增益
```

可選擇再加入：

```text
已知取得來源
未知取得來源
已符合學習條件但尚未取得
```

是否讓玩家看到尚未發現的能力／來源，可由 GM 或 Campaign 設定控制。

---

## 5. 「已取得」與「可使用」保持分離

沿用既有 Canonical：

```text
能力存在
↓
角色取得能力
↓
檢查目前使用資格
```

所以技能樹可以清楚顯示：

```text
末日
屬性：火
階級：九階

狀態：已取得
使用狀態：目前不可使用
原因：火屬性階級不足
```

角色日後達到條件時，狀態可以自動變成：

```text
已取得・可使用
```

不需要重新學習。

---

## 6. 技能樹中的連線不是「購買路徑」

節點之間仍然可以有連線，但含義應該是資訊／關係，而不是「花技能點逐格買上去」。

例如：

```text
前置能力
進階版本
衍生能力
同一流派
同一學校／門派
同一元素系
同一武技系
互斥／替代
相關能力
```

例：

```text
火球術
   │
   ├── 連環火球
   └── 爆裂火球
```

這代表三者有能力關係，並不代表角色只要學會火球術，就可以直接在 UI 點擊解鎖另外兩招。

真正取得仍需要對應世界來源。

---

## 7. 能力前置仍然有效

取消「技能樹直接解鎖」不代表取消能力前置。

例如某能力可以要求：

```text
火屬性階級 ≥ 3
已取得：火球術
已取得：魔力控制
```

玩家找到能教授該能力的導師／卷軸／學校時，系統才檢查這些條件。

因此：

```text
前置條件
=
能否學習／能否使用的規則
```

而不是：

```text
前置條件
=
技能樹上必須先花點數走過的節點
```

---

## 8. 技能點不再直接購買具名能力

若系統保留「技能點」，技能點不得預設用於：

```text
點擊火球術 → 立即學會
點擊月牙斬 → 立即學會
點擊治療術 → 立即學會
```

技能點的最終用途需另行確定。

Alpha 暫定：

```text
技能點可用於角色本身的技能／熟練度／成長系統
```

但不直接等同「能力購買貨幣」。

技能點具體提升規則仍屬待定項目，不在本文件鎖死。

---

## 9. 建議玩家頁視覺

技能樹頁仍可以保留 PoE 類型的可縮放圖譜視覺，但互動語意改變。

例如：

```text
火元素
│
├─ 火球術                  已取得・可使用
│   ├─ 連環火球            未取得
│   └─ 爆裂火球            已取得・不可使用
│
├─ 火焰附魔                已取得・可使用
└─ 末日                    已取得・不可使用
```

點擊節點後顯示：

```text
能力名稱
屬性
階級
能力效果
目前狀態
目前是否可使用
缺少條件
已知取得來源
前置能力
相關能力
```

不提供：

```text
[消耗技能點解鎖]
```

---

## 10. 已知取得來源可以成為重要玩法資訊

技能圖譜可以在玩家已知相關情報後顯示：

```text
火焰附魔
取得來源：王都魔法學院・附魔課程
```

```text
連環火球
取得來源：赤炎塔導師／連環火球卷軸
```

```text
末日
取得來源：未知
```

這樣技能圖譜可以兼任：

- 角色能力狀態頁；
- 成長方向參考；
- 世界探索線索；
- 已知學習途徑整理。

但不會取代遊戲世界內真正的學習／取得行為。

---

## 11. GM 端能力圖譜權限更高

GM 應可：

```text
將能力加入／移出角色
設定角色是否已取得
設定能力來源
設定玩家是否已知取得來源
設定／修改前置條件
設定能力關係連線
設定能力是否公開顯示
查看角色目前可用／不可用原因
直接越過一般取得條件授予能力
```

GM 修改能力本身時，仍使用既有 AI + GM 編輯系統。

---

## 12. Alpha 鎖定方向

1. 技能樹不再是具名能力的直接解鎖／購買系統。
2. 升級、屬性階級提升或技能值提升不會自動令角色學會新的具名能力。
3. 角色取得能力主要來自遊戲世界中的導師、師傅、學校、門派、卷軸、秘籍、物品、商店、任務、劇情、覺醒或 GM 授予等來源。
4. 商店、卷軸、物品等可在規則允許時由玩家自行完成取得，不需要 GM 每次手動授予。
5. 技能樹／能力圖譜負責顯示角色能力狀態、前置、關係、使用資格與已知取得來源。
6. 已取得與可使用必須分離；角色可以擁有目前不能使用的能力。
7. 技能樹節點之間的連線代表前置／衍生／流派／相關等關係，不代表可逐節點購買。
8. 能力前置仍存在，但在真正學習／使用時驗證，而不是用作 UI 點數路徑。
9. 技能點不再預設直接購買具名能力；其具體用途另行確定。
10. GM 可以控制能力圖譜的公開程度、取得來源資訊、角色能力狀態與關係。
11. 所有正式能力、角色取得狀態與來源資料仍保存於 D1。
