# 狀態效果標準結構 — Alpha

> 狀態：Canonical Alpha 規格
> 目的：為 AI 生成能力、戰鬥處理、增益／減益、GM 審批與 D1 儲存建立統一的狀態效果結構。
> 原則：先固定結構與分類；精確成功率、抗性公式、各狀態數值強度可於 Alpha Build 再調整。

---

## 1. 屬性與效果必須分離

能力的「屬性」不等於「效果」。

正式屬性可包括：

```text
物理
光
暗
火
水
風
土
雷
木
無屬性
```

效果則描述能力實際造成甚麼，例如：

```text
傷害
治療
增益
減益
控制
位移
召喚
環境改變
特殊效果
```

因此同一種狀態可以由不同屬性造成。

例：

```text
雷元素 + 暈眩
暗元素 + 魅惑
光元素 + 幻覺
水元素 + 幻覺
木元素 + 睡眠
物理 + 暈眩
無屬性 + 精神控制
```

不得因為能力造成精神／感知效果，就自動新增「精神元素」「幻術元素」等新元素。

---

## 2. 狀態效果四個主要作用層面

每個持續性狀態至少標記一個「作用層面」：

```text
身體
精神
感知
環境
```

可複選。

例：

```text
燃燒 → 身體
魅惑 → 精神
幻覺 → 感知
濃霧 → 環境 + 感知
睡眠 → 身體 + 精神
```

作用層面主要供 AI 判斷、未來抗性／免疫系統、淨化與解除條件使用。

---

## 3. 標準效果分類

### 3.1 持續傷害

```text
燃燒
流血
中毒
腐蝕
感電／電擊殘留
```

通常包含：

```text
每回合傷害
持續回合數
觸發時點
是否可疊加
解除條件
```

### 3.2 行動控制

```text
暈眩
定身
睡眠
沉默
繳械
束縛
```

主要影響角色可採取的行動。

### 3.3 精神控制

```text
迷惑
魅惑
恐懼
混亂
支配
```

強度差異必須由能力階級／Power Budget 支付；「支配」不可被當成與普通迷惑相同成本。

### 3.4 感知干擾

```text
致盲
幻覺
幻聽
假目標
感知扭曲
距離誤判
方向誤判
```

此類效果不等於精神控制。

例如：

```text
幻覺
→ 目標感知到不存在的事物

魅惑
→ 目標的態度／意志受到精神影響
```

兩者在 AI 判定、抗性與解除方式上可以完全不同。

### 3.5 行動／數值修正

```text
緩速
加速
命中下降
命中提升
防禦下降
防禦提升
傷害下降
傷害提升
魔力消耗修正
```

此類通常以增益／減益記錄，而不是建立大量獨立硬編碼狀態。

### 3.6 恢復／持續支援

```text
再生
持續治療
護盾
抗性提升
淨化保護
```

仍視為 Buff／狀態效果；不等同立即治療。

---

## 4. 即時效果與持續狀態分離

不是所有效果都應建立狀態紀錄。

即時效果，例如：

```text
推離
拉近
擊退
位置交換
瞬間治療
一次性傷害
解除一個狀態
```

通常在能力結算時立即處理，不需要建立「剩餘回合」狀態。

持續效果，例如：

```text
燃燒 3 回合
暈眩 1 回合
幻覺 2 回合
火焰附魔 3 回合
劍類專精（永久）
```

才建立持續狀態／增益紀錄。

---

## 5. 時間單位

所有戰鬥中的有限持續時間，正式以「回合」為標準單位。

例：

```text
持續：1 回合
持續：3 回合
持續：5 回合
```

不得在核心戰鬥規則內混用：

```text
30 秒
1 分鐘
2 回合
```

如劇情需要現實時間，應在進入戰鬥處理時轉換成回合或由 GM 決定。

永久／常駐效果使用：

```text
持續類型：永久
```

而不是極大的回合數。

---

## 6. 常駐增益與限時增益

### 常駐增益

例如：

```text
劍類專精
徒手專精
永久天賦
訓練成果
```

特徵：

```text
無回合倒數
通常由角色成長、天賦、專精、永久效果取得
只有條件不符合或被規則移除時停止生效
```

### 限時增益／減益

例如：

```text
火焰附魔：3 回合
加速：2 回合
恐懼：2 回合
幻覺：3 回合
```

特徵：

```text
有剩餘回合
每個回合按規則遞減
可由淨化／解除／條件提前終止
```

---

## 7. 狀態資料結構

概念結構：

```text
狀態效果
├── 名稱
├── 類別
├── 作用層面[]
├── 來源屬性
├── 來源能力
├── 來源角色／物件
├── 持續類型：即時 | 回合制 | 永久
├── 剩餘回合 nullable
├── 效果資料[]
├── 觸發時點
├── 疊加規則
├── 解除標籤[]
├── 限制／免疫條件[]
└── metadata
```

D1 內部欄位可使用英文技術識別，但玩家／GM 可見內容與正式自然語言資料使用繁體中文。

---

## 8. 疊加規則必須明確

每個狀態定義應指定其中一種疊加政策：

```text
不可疊加
→ 已存在時不新增第二層

刷新時間
→ 再次施加時重設剩餘回合

延長時間
→ 再次施加時增加剩餘回合

增加層數
→ 每次施加增加 Stack，最多 N 層

取較強者
→ 同類效果只保留數值較高者

取最新者
→ 新效果取代舊效果
```

AI 生成能力時必須選擇一種；不可只寫「可疊加」但沒有上限或行為。

精確 Stack 上限與數值留待 Alpha 平衡。

---

## 9. 觸發時點

持續效果應標準化觸發時點，例如：

```text
施加時立即
目標回合開始
目標回合結束
來源角色回合開始
每次成功攻擊後
受到傷害後
使用指定類型能力時
```

例：

```text
燃燒
→ 目標回合結束時造成傷害

再生
→ 目標回合開始時恢復生命值

火焰附魔
→ 成功物理攻擊後追加附魔效果
```

精確預設可於 Alpha Build 統一，但資料模型必須支援。

---

## 10. AI 生成狀態時的責任

AI 不只決定狀態名稱，還要根據能力概念與 Reference Scale 產生完整結構，例如：

```text
狀態：幻覺
類別：感知干擾
作用層面：感知
持續：2 回合
效果：命中判定降低
疊加：不可疊加；再次施加刷新時間
解除：淨化／特定感知能力／能力指定條件
```

狀態強度、持續時間、觸發方式、附加傷害等全部屬於能力 Power Budget 的一部分，不可免費附加。

---

## 11. 歧義名稱先澄清再生成

若能力名稱可能合理對應多種狀態機制，先使用 AI 歧義澄清流程。

例：

```text
名稱：萬華鏡
範圍：範圍
```

AI 可提出：

```text
A. 幻象迷宮
偏向：幻覺／感知干擾／假目標

B. 光學折射
偏向：致盲／距離誤判／方向誤判
```

玩家選擇方向後，AI 才生成正式階級、魔力、持續回合、數值與效果。

---

## 12. 「萬華鏡」完整示例

假設玩家選擇「幻象迷宮」方向，AI 可能生成：

```text
能力名稱：萬華鏡
屬性：光
效果類別：控制
作用層面：感知
狀態：幻覺

效果：
範圍內目標會看見多個虛假影像，難以確認真實位置。

持續時間：2 回合

機械效果：
命中判定受到減益

疊加規則：
不可疊加；再次施加刷新持續時間
```

具體減益數值、階級與魔力消耗由 Reference Scale + AI 平衡生成，再經玩家確認與 GM 審批。

## 14. 暫不鎖定的 Alpha 平衡項目

以下可留待 Alpha Build／實測：

```text
精神／感知／身體抗性使用甚麼角色數值
狀態命中與抵抗是否需要對抗判定
每個階級可負擔的控制強度
暈眩／支配等強控制的最大持續時間
Stack 上限
解除／淨化成本
Boss／特殊單位的控制抗性
```

這些平衡細節不得阻礙目前資料結構與 AI 生成流程。

---

## 15. Alpha 鎖定方向

1. 屬性與效果類別完全分離。
2. 精神、幻覺、控制等不新增為元素。
3. 狀態至少可標記身體、精神、感知、環境作用層面。
4. 控制細分為行動控制、精神控制、感知干擾等類別。
5. 推離、拉近、擊退等一次性效果預設是即時效果，不必建立持續狀態。
6. 所有限時戰鬥效果以「回合」為時間單位。
7. 專精等永久能力可表示為常駐增益，不使用回合倒數。
8. 每個狀態必須有明確疊加規則。
9. AI 生成的狀態強度、時間、疊加、解除與附加效果都計入 Power Budget。
10. AI 對高歧義名稱先提供 2 個、最多 3 個方向讓玩家確認，再生成完整機械數值。
11. Alpha 標準狀態詞彙是參考表，不是封閉列表。
12. 新狀態必須使用同一結構化資料模型。
13. 玩家確認後才送 GM；GM 批准後才成為正式能力／狀態定義。
14. 正式可見與自然語言內容均使用繁體中文；英文只保留於內部技術識別。
