# A. 混合招式系統

**狀態：DEFERRED**

## 目前決定

混合招式暫時不作為目前 Alpha 核心規則的一部分。

目前 Alpha 先維持：

- 魔法能力主要由對應元素階級／修習處理；
- 物理能力主要由對應武器專精處理；
- `物理` 保留作能力／傷害分類，不再作獨立角色成長軸；
- 不建立 `物理倍率 × 武器專精倍率` 的雙重成長乘法；
- 不因少數混合招式而改動目前整套成長架構。

## 未來需要處理

### A1. 多來源標示

例如：

```text
炎龍劍式
├─ 武器系：劍
├─ 元素：火
└─ 類型：混合招式
```

需決定：

- 多個平等來源；或
- 主要來源／次要來源。

### A2. 使用資格

需要決定混合招式是否要求：

```text
劍類專精 ≥ X
且
火元素階級 ≥ Y
```

或其他主次條件／最低條件模型。

### A3. 修習 EXP 分配

一次使用只可產生一份總修習預算。

可於未來測試例如：

```text
劍類專精 60%
火元素 40%
```

實際權重不得在現階段寫死。

### A4. 威力計算

禁止：

```text
完整劍專精倍率 × 完整火元素倍率
```

亦禁止：

```text
完整物理預算 + 完整火元素預算
```

一個混合招式只可有一份總威力 Budget。

未來可研究：

- 主來源提供基礎框架，次來源改變效果；
- 總 Budget 按來源比例分配；
- AI Reference/Scale 直接生成單一混合 Profile。

### A5. 武器與元素責任分工

例如炎龍劍式可考慮：

- 劍類專精：命中、操控、連擊、反擊、武器技巧；
- 火元素：火焰傷害、燃燒、元素效果；
- 不允許兩者各自完整放大同一項輸出。

### A6. 混合招式階級

需研究是否採單一能力階級：

```text
炎龍劍式：五階
```

另外保存學習／使用條件：

```text
劍類專精 ≥ 4
火元素 ≥ 3
```

而不是把同一招拆成兩個完整階級倍率。

### A7. AI 判斷

未來 AI 應能分辨：

```text
純武器技
純元素魔法
附魔
真正混合招式
```

語意不明時沿用 AI 歧義澄清模式。

### A8. 附魔與混合招式分離

```text
火焰附魔 + 普通劍擊
≠
炎龍劍式
```

前者為攻擊來源 + Buff；後者為能力本身同時要求兩種操控來源。

### A9. 三重以上來源

未來可能出現：

```text
劍 + 火 + 風
雙武器 + 雷
徒手 + 土
```

需考慮：

- 最大來源數；
- 遞減收益；
- 總威力 Budget；
- 修習 EXP 總量限制。

### A10. UI

未來能力頁可顯示：

```text
炎龍劍式
混合招式
劍類 / 火
五階
```

暫不建立獨立「混合」主分頁。

## 不可違反原則

1. 一次使用只產生一份總修習預算。
2. 一個能力只使用一份總威力預算。
3. 不允許多個完整倍率互乘造成後期爆炸。
4. 附魔攻擊與真正混合招式必須分開。

# B. 元素／武器專精修習 EXP 曲線

**狀態：ALPHA_TUNING**

目前只鎖定存在獨立修習進度；實際數字留待 Alpha。

未來需測試：

- 每階需要多少修習 EXP；
- 高階是否使用非線性需求；
- 0→1 與 8→9 的成長差距；
- 實際使用、正式訓練、導師教學、劇情獎勵各自的 EXP 權重；
- 防止重複施法／重複揮武器刷 EXP；
- 是否需要每日／場景／戰鬥軟上限；
- 滿 EXP 後是否直接升階或需要突破條件。

# C. 武器專精成長與獎勵曲線

**狀態：ALPHA_TUNING**

目前決定：

- 物理不再有獨立角色總階級；
- 劍、槍／矛、錘、徒手等武器／戰鬥方式可各自成長；
- 專一使用自然獲得更高深度；
- 玩家可以多修，但不額外禁止。

未來需測試：

- 各專精階級／稱號；
- 升階需要多少 EXP；
- 專精提供哪些永久優勢；
- 傷害、命中、控制、反擊、破防等 Bonus 如何避免後期膨脹；
- 是否需要遞減收益；
- 是否容許極高專精突破一般效果上限；
- 單武器專精的獎勵是否足夠鼓勵專一玩法。

# H. Character Level 升級技能點

**狀態：ALPHA_TUNING**

目前已鎖定：

- Character EXP → Level 保留；
- Level-up 可授予技能點（SP）；
- SP 主要用於提升 22 個基礎技能；
- SP 不直接購買／解鎖具名能力；
- 基礎技能另可透過有效 D100 判定的大成功產生使用成長。

未來只需調整：

- 每級實際授予多少 SP；
- SP 是否 `1 SP = +1`；
- 高技能區間是否提高 SP 成本；
- Creation SP 與 Level-up SP 是否使用完全相同的消耗曲線；
- 多級一次跨越時如何補發。

工作簿的 +5／Level 僅作參考，不視為最終數值。

# K. 基礎技能大成功成長曲線

**狀態：ALPHA_TUNING**

目前已鎖定：

- 基礎技能採 `SP + 使用成長`；
- 使用成長只在有效 D100 判定取得大成功時觸發；
- 大成功先產生成長進度／標記，不直接令技能值 +1；
- 普通成功、失敗、大失敗不產生使用成長；
- 無意義刷骰不產生成長。

未來 Alpha 需測試：

- 一次大成功提供多少成長進度；
- 多少成長進度換取 +1 技能值；
- 高技能區間是否需要更多成長進度；
- 是否需要每場景／每 Session 的同技能成長軟上限；
- SP 成長與大成功成長同時存在時的總成長速度；
- 最高技能值附近的遞減收益／硬上限；
- 統一 D100 骰點結果系統對「大成功」的精確門檻。

# L. 過量治療失控與體質承受系統

**狀態：DEFERRED**

## 目前 Alpha 已鎖定

目前 Alpha 只保留最簡單的 Overheal 流程：

```text
Overheal Amount > 0
→ GM-only 50% Random Check

Success
→ floor(Overheal Amount / 2) 轉為 Hidden Temporary HP

Failure
→ Overheal 全部消散
```

並且：

- Temporary HP 的精確值只供 GM／系統查看；
- Player 不顯示 Temporary HP 數值；
- Temporary HP 不改寫 Max HP；
- Damage 先消耗 Hidden Temporary HP，再扣 Current HP；
- Hidden Temporary HP 可用作故事上「生命力旺盛／恢復較快」的合理化，但 Alpha 不自動提供真正 Buff。

## 為何延後

若加入「過量生命過高會產生副作用」，會牽涉：

```text
角色體質
種族／身體結構
治療來源
生命能量類型
狀態效果
抗性／豁免
Temporary HP 上限
AI 情境推演
```

容易令 Alpha Healing Resolver 膨脹成另一套完整狀態／生理系統，因此先延後。

## 未來需要研究

### L1. Overheal Load／失控線

可研究：

```text
(Max HP + Temporary HP) / Max HP
```

作為 Overheal Load。

早期構思曾以：

```text
200% Max HP
```

作「開始出現失控風險」的參考點，但 **目前並未鎖定 200% 為正式門檻**。

未來需測試是否：

- 200% 合理；
- 應按種族／體型／能力改變；
- 使用固定線或逐步風險曲線。

### L2. CON／體質作承受能力

未來可考慮使用：

```text
CON／體質
```

作為角色承受過量生命、異常再生或身體增生的主要合理化來源之一。

需要決定：

- CON 是固定門檻、Bonus、抵抗值還是 D100 來源；
- 高 CON 是否只是減輕副作用，還是提高安全 Temporary HP 區間；
- 是否需要與 SIZ、種族、身體結構共同計算；
- 魔法／機械／不死／植物生命是否應使用不同屬性。

### L3. 過量治療副作用

未來可能方向：

```text
組織過度增生
再生失控
腫脹／身體比例異常
過剩生命能量外溢
活動控制下降
異常器官／組織短暫形成
植物生命枝芽／根系擴張
其他符合種族與治療來源的變化
```

上述效果不可直接固定成同一張懲罰表。

### L4. AI + GM 推演

如果未來正式加入 Overheal Overload：

```text
系統偵測達到風險條件
→ AI 提供 1–3 個合理副作用／故事結果
→ GM 接受／修改／拒絕
```

AI 應參考：

```text
CON／體質
種族／身體結構
Overheal Load
治療來源
既有狀態
環境
世界規則
```

### L5. 正面機械效果

未來亦可研究 Hidden Temporary HP 是否可在某些條件下合理提供：

```text
自然恢復加快
疲勞恢復加快
短暫再生
某些狀態抗性提升
```

但不可因 Temporary HP 存在就全域自動獲得免費 Buff。

### L6. 隱藏資訊原則

即使未來 Overheal 系統擴充，預設仍應保留：

```text
Temporary HP 精確數值
→ GM-only
```

若要讓玩家感受到異常生命力，優先使用敘事提示／狀態描述，而不是直接顯示隱藏 HP 數字。

## 不可違反原則

1. 目前 Alpha 的 50% GM-only Overheal Check 不因 Future Design 尚未完成而改變。
2. Temporary HP 不直接改寫 Max HP。
3. 隱藏 Temporary HP 的精確數值預設只供 GM／系統查看。
4. Overheal 副作用必須有合理世界／生理因果，不使用無條件固定懲罰表。
5. Future Overheal 機械效果須由正式 Status／Effect Resolver 處理，不可只靠 AI 偷偷改數值。

# M. 格仔地圖、移動與戰場空間規則

**狀態：PLANNED / DEFERRED**

## 目前 Alpha 已鎖定

目前戰鬥只鎖定最小格仔距離模型：

```text
以角色所在格為中心
周圍八格全部視為距離 1
包括四個斜角
```

即斜角鄰接不使用 1.5 格、2 格或額外移動成本。

另外已鎖定：

```text
每回合有 1 次移動
```

但「一次移動可走幾格」尚未決定。

## 為何延後

完整地圖系統會牽涉大量互相關聯規則，若現在加入會拖慢 Combat Alpha：

```text
移動速度
地形成本
障礙物
視線
掩體
高低差
範圍模板
大型單位佔格
單位碰撞
穿越友軍／敵軍
強制位移
地圖 UI
```

因此目前只保留最小九宮格鄰接規則。

## 未來需要處理

### M1. 每回合移動格數

需決定：

- 固定每回合 N 格；
- 由 DEX／SIZ／種族／裝備等推導；
- Buff／Debuff 如何改變移動格數；
- 跑步、衝刺等是否消耗主行動換更多移動。

### M2. 地形與障礙

需定義：

```text
普通地形
困難地形
不可通行格
門／牆／障礙物
水域
高低差
```

以及每類地形是否改變移動成本。

### M3. 視線與掩體

需決定：

- 直線視線算法；
- 半掩體／全掩體；
- 斜角牆如何判斷；
- 遠程攻擊、魔法、範圍效果如何讀取掩體。

### M4. 單位佔格

需研究：

- 一般角色 1 格；
- 大型／巨型單位多格佔位；
- 大型單位的鄰接範圍；
- 可否與友軍共享格；
- 召喚物／環境物件如何佔格。

### M5. 強制位移與碰撞

需定義：

- 擊退／拉近／推離如何逐格移動；
- 撞牆／撞單位後如何處理剩餘位移；
- 斜角強制位移是否仍每格成本 1；
- 是否會觸發環境傷害或額外狀態。

### M6. 範圍模板

未來需支援：

```text
單體
多目標
直線
錐形
圓形／半徑
環形
其他特殊區域
```

範圍計格須與「八方向鄰接皆為 1」保持一致，避免同一系統使用兩種距離度量。

## 不可違反原則

1. Alpha 已鎖定八方向相鄰格，包括斜角，全部計距離 1。
2. 每回合維持 `1 主行動 + 1 移動` 的基本行動經濟，除非未來明確版本覆蓋。
3. 地圖系統不得偷偷改寫 D100 命中／對抗核心；若地形提供優勢，應以明確修正／Profile 表示。
4. 完整 Map 規則正式確立前，不在 Combat Alpha 偷偷寫死每回合移動格數。

# Future Update 全域原則

1. Future idea 不得因為尚未完成而偷偷影響目前 Alpha Canonical 規則。
2. 所有數值曲線盡量做成可配置，避免寫死後難以 Alpha 調整。
3. D1 仍為唯一持久資料來源。
4. 玩家／GM 可見內容使用繁體中文。
5. AI 建議不是最終權威；GM 可調整 AI 提供數值。
6. Future Update 一律集中更新本文件，不再拆新 Future Update 文件。
