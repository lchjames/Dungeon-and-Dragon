# 基礎動作與 MP 資源消耗 — Alpha

> 狀態：Canonical Alpha Working Rule  
> 範圍：基礎動作、普通攻擊、具名能力、MP 成本、MP=0 行為、AI 資源成本建議。  
> 本文件覆蓋較早規格中「物理能力資源成本日後才決定」或可能將所有普通物理行動視為具名技能／能力的描述。

---

# 1. 核心分層：基礎動作 ≠ 基礎技能 ≠ 具名能力

Alpha 正式分成三層：

```text
基礎動作
→ 角色因身體、持有物或裝備而自然可以做的行動
→ 不需要學習
→ 不需要解鎖
→ 預設 0 MP

基礎技能
→ 察覺、運動、投擲、閃避等 D100 判定能力
→ 用來判斷角色做某件事做得有多好
→ 不等於一個具名招式

具名能力／招式／法術
→ 月牙斬、火球術、治療術、彈反劍式等
→ 有正式 Ability / Effect Profile
→ 需要取得／學習
→ 主動使用時需要支付資源
```

因此：

```text
「我揮拳」
≠ 必須先擁有一個叫「揮拳」的能力

「我踢他」
≠ 必須先學習「踢擊」

「我拿劍斬他」
≠ 必須先學習「普通斬擊」
```

這些均可作為基礎動作存在。

---

# 2. Alpha 基礎動作表

基礎動作不是封閉清單，但 Alpha 至少支援：

| 基礎動作 | 典型例子 | 資源成本 | 主要解析來源 |
|---|---|---:|---|
| 徒手普通攻擊 | 拳、腳、肘、膝、頭撞 | 0 MP | 徒手／身體 Source + 對應物理專精脈絡 |
| 武器普通攻擊 | 揮劍、刺槍、砍斧、敲錘 | 0 MP | 裝備武器 Damage Profile + 對應武器專精脈絡 |
| 投擲 | 石頭、瓶、飛刀、其他可投物 | 0 MP | `投擲` 基礎技能 + 投擲物 Source/Profile |
| 推／撞／拉扯 | 推開、撞倒、拉離位置 | 0 MP | 通常使用 `運動` 或相應對抗；具體效果依情境 |
| 一般身體動作 | 跳、攀爬、翻越、搬動 | 0 MP | `運動`／`身法` 等相關基礎技能 |
| 一般互動 | 開門、按機關、使用普通可互動物件 | 0 MP，本身仍可能消耗主行動 | 物件／場景規則 |

換武器、飲藥、拾取物品等是否消耗主行動，沿用 `戰鬥回合與行動經濟_ALPHA.md`。

基礎動作可以需要 D100 判定，但「需要判定」不會把它變成具名能力。

---

# 3. 普通攻擊不建立一堆假技能

Alpha 不為以下每一項建立獨立 Ability：

```text
左拳
右拳
前踢
側踢
肘擊
劍橫斬
劍直劈
普通刺擊
普通揮棍
```

它們預設只是同一類基礎動作的自然描述。

普通物理攻擊的結算應讀取：

```text
使用者
實際 Attack Source（身體／武器／物品）
對應武器／徒手專精脈絡
Source Damage Profile
角色 Damage Bonus（如適用）
Buff / Debuff
目標防守／閃避
場景條件
```

然後沿用既有 D100 對抗與 Damage Resolver。

普通攻擊造成的物理修習，仍可推進實際使用的武器／徒手專精；它不需要是一個具名能力才算「使用該專精」。

---

# 4. 何時普通動作升格為具名能力

系統先嘗試將玩家描述映射到既有基礎動作。

例如：

```text
「我一拳打他」
→ 徒手普通攻擊

「我踢他」
→ 徒手普通攻擊

「我用劍斬他」
→ 武器普通攻擊
```

但若玩家要求明確超出普通動作的特殊機械效果，例如：

```text
旋身飛踢並固定擊退三格
一劍同時斬三個目標
普通斬擊同時附帶暈眩兩回合
瞬間跨越數格後反擊
```

則可能屬於：

```text
具名能力
特殊 Ability Profile
或 GM 明確批准的特殊情境行動
```

AI 可協助判斷「普通動作」與「需要 Ability Profile」的界線，但不得因玩家只是換一種自然語言描述，就自動生成新能力。

---

# 5. Active Ability 的 Alpha 資源：MP

為保持 Alpha 簡單，所有需要主動啟動的具名能力，無論屬於：

```text
物理
光
暗
火
水
風
土
雷
木
```

預設都使用 MP 作主要施放資源。

這代表具名物理招式亦屬於「超出普通物理動作的技巧／能量輸出」，預設需要支付 MP。

Alpha 不另外建立 Stamina、氣力、怒氣、法力等多條資源池。

被動能力如果本身沒有 upkeep／啟動成本，不視為「主動使用技能」，可以在 MP=0 時繼續存在；具體仍按其 Profile。

---

# 6. MP 成本只提供一張 Default Reference Table

Alpha 不為每個技能手工寫死統一成本公式。

先提供一張按 Ability Rank 的預設 MP 參考表：

| Ability Rank | Default MP Cost |
|---:|---:|
| 1 | 2 |
| 2 | 3 |
| 3 | 5 |
| 4 | 7 |
| 5 | 10 |
| 6 | 14 |
| 7 | 19 |
| 8 | 25 |
| 9 | 32 |

此表是 **Reference，不是所有能力不可偏離的硬公式**。

AI 生成／平衡能力時，以：

```text
Ability Rank
Default MP Cost
能力總 Power Budget
```

作起點，再按實際能力設計調整。

AI 可參考：

```text
傷害／治療量
目標數
範圍
射程
持續時間
多段／多投射物
控制強度
Buff / Debuff
可靠性
特殊例外
限制條件
冷卻／使用限制（如 Profile 有）
武器／Item Source
物理或元素脈絡
```

若實際 MP Cost 偏離 Default，AI 必須提供簡短理由；玩家確認後再送 GM，GM 最終批准／修改／拒絕。

---

# 7. Active Ability 最低成本原則

為保留「MP=0 時只能使用普通物理行動」的 Alpha 設計：

```text
主動具名能力
→ 預設 MP Cost >= 1
```

所以不得把一個實際上是特殊招式的能力包裝成：

```text
Active Ability
MP Cost = 0
```

以繞過資源系統。

真正 0 MP 的主動物理行為應優先判斷為「基礎動作」，而不是具名能力。

未來如要加入其他資源池、Charges、HP Cost、特殊零成本能力等，另行擴充；Alpha 不處理。

---

# 8. MP = 0 時可以做甚麼

Canonical Alpha：

```text
Current MP = 0
```

角色仍然可以：

```text
移動
徒手普通攻擊
武器普通攻擊
投擲
推／撞／一般身體行動
換武器／拾物／飲藥等一般行動（按行動經濟）
被動閃避／抵抗／防守
不需要啟動／upkeep MP 的被動能力與狀態
```

但不能主動使用需要 MP 的具名能力／招式／法術。

所以：

```text
MP = 0
≠ 角色甚麼都做不到

MP = 0
= 失去主動特殊能力輸出，退回普通物理／一般行動
```

MP 不可因施放而降至負數。

---

# 9. MP 支付時點

Alpha 預設：

```text
宣告並正式啟動 Ability
→ 檢查 Current MP >= MP Cost
→ 支付 MP
→ 再進入 D100／對抗／效果結算
```

因此：

```text
普通失敗
大失敗
被對方成功抵抗
最終沒有命中
```

預設都不退款。

同樣：

```text
大成功
→ 效果按 Great 規則放大
→ 不額外再支付雙倍 MP
```

除非 Ability Profile 明確有其他規則。

---

# 10. AI 不需要參與每一次普通攻擊

常見基礎動作應直接由 Default Action Profile + 既有 Resolver 處理。

AI 主要在以下情況介入：

```text
玩家描述無法明確映射到普通動作
使用臨時／奇怪物件作攻擊來源
動作可能橫跨「普通動作」與「特殊能力」界線
需要由 Reference Table 推導新 Ability MP Cost
特殊目標／環境令普通 Profile 不足以描述
```

AI 可提供 1–3 個合理解析／成本建議；GM 為最終裁決者。

---

# 11. 與既有基礎技能的關係

基礎技能可以作為「基礎動作的 Resolver」，但不是動作本身。

例如：

```text
推人
→ 基礎動作
→ 可使用 運動 作 D100 對抗

丟石頭
→ 基礎動作
→ 使用 投擲

避開攻擊
→ 被動防守
→ 使用 閃避
```

普通劍擊／徒手攻擊則主要沿用實際武器／徒手專精脈絡與 Attack Source Profile；不重新建立 `Melee`／`Ranged` 基礎技能，避免推翻既有 23 基礎技能重構。

對應武器／徒手專精如何映射成普通攻擊的精確 D100 基礎數值，可由物理 Default Reference Table 另行定義；本文件只鎖定「不需要為每個普通攻擊建立具名能力」。

---

# 12. Alpha 鎖定結論

1. 基礎動作、基礎技能、具名能力正式分離。
2. 拳、腳、普通揮劍／刺擊等是基礎動作，不需要學習或建立 Ability。
3. 基礎動作預設 0 MP；具名 Active Ability 預設需要 MP。
4. Alpha 所有主動具名物理／元素能力預設共用 MP，不另建 Stamina／氣力等資源池。
5. 主動具名能力預設 MP Cost 至少 1；真正 0 MP 的普通行為應歸類為基礎動作。
6. MP=0 時仍可移動、普通徒手／武器攻擊、投擲、一般互動及被動防守，但不能啟動需要 MP 的具名能力。
7. Ability Rank 1–9 使用一張 Default MP Cost Reference Table；實際能力成本由 AI 按 Power Budget／用途提出調整並說明理由，GM 最終批准。
8. MP 在 Ability 正式啟動時支付；失敗／大失敗／被抵抗預設不退款；大成功不追加 MP。
9. 普通物理攻擊沿用實際 Attack Source、Damage Profile、武器／徒手專精脈絡與既有 D100／Damage Resolver。
10. `Melee`／`Ranged` 不重新加入基礎技能表。
11. AI 不需要參與每次普通攻擊；只在歧義、即興來源、特殊行動或新 Ability 平衡時介入。
12. 所有正式 Ability、MP、Profile、專精與裁決資料保存於 D1。
