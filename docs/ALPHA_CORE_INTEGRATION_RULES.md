# Alpha Core Integration Rules

> Status: **Canonical Alpha Integration Rule**  
> Date: 2026-08-20  
> Scope: EXP/Level authority, resource recalculation, HP/MP recovery, Character creation flow, GM authority, round/turn lifecycle, migration and authentication.  
> This document records the latest confirmed integration decisions and overrides older conflicting Alpha implementation notes until those files are fully consolidated.

---

# 1. EXP and Level Authority

## 1.1 EXP is authoritative

```text
Starting EXP = 1
Starting Level = 1
```

Level is derived automatically from cumulative EXP using the current Level 1–100 Canonical threshold resolver.

Player cannot directly edit EXP or Level.

## 1.2 Level 100 cap does not cap EXP

```text
Level <= 100
EXP may continue increasing above the Level 100 threshold
```

At or above the Level 100 threshold, the resolver keeps `Level = 100` while preserving the full cumulative EXP total.

## 1.3 GM EXP controls

GM may:

```text
Add EXP
Subtract EXP
Set Total EXP directly
```

Every EXP adjustment must be server-side, auditable and followed by a Level recalculation.

## 1.4 GM high-Level Character creation

Normal Player-created Characters begin at Level 1 / EXP 1.

GM may choose a Starting Level for a GM-created/imported Character. The server converts that Level into the minimum EXP threshold for that Level and stores EXP as the authoritative progression value.

---

# 2. Level / Attribute Changes and Current Resources

When a permanent change increases Max HP or Max MP:

```text
Increase in Current Resource
= New Max - Old Max
```

Example:

```text
Old Current HP = 20
Old Max HP = 35
New Max HP = 37

New Current HP = 22
```

The same rule applies to MP.

This preserves existing missing HP/MP rather than fully healing the Character or keeping the old Current value unchanged.

If a permanent recalculation reduces a Max value:

```text
Current = min(Current, New Max)
```

Current values may never exceed their final Max values through ordinary recalculation.

---

# 3. HP / MP Max Structure

Canonical calculated values remain formula-driven.

```text
Calculated Max HP
= ceil(Base HP × G(Level))

Calculated Max MP
= floor(Base MP × G(Level))
```

Final Max values use explicit modifiers rather than silent formula overrides:

```text
Final Max HP
= Calculated Max HP + HP Max Modifier

Final Max MP
= Calculated Max MP + MP Max Modifier
```

GM may update the modifier values directly through the GM interface.

The underlying Canonical formulas are not directly editable through ordinary Character editing.

Future equipment, permanent effects, Buffs or other approved sources may be represented through structured modifiers rather than rewriting the calculated base formula.

---

# 4. Character Creation Attribute Flow

Core Attributes are generated by the system using the existing Canonical Character-generation rules.

Before final confirmation:

```text
System Roll
→ Player may Reroll
→ Player confirms final generated set
```

The Player does not manually type arbitrary permanent starting Attribute values.

The exact reroll cap, if any, is not changed by this decision unless separately locked; the required Alpha interaction is that reroll and explicit confirmation are supported.

After confirmation, the Character is created with derived HP/MP calculated from the confirmed Attributes and Level.

---

# 5. Player / GM Resource Authority

Player-facing HP and MP are not arbitrary numeric edit fields.

Player resource changes should normally come from system-resolved gameplay events such as:

```text
Damage
Healing
Ability cost
Focus
Rest
Item / Effect resolution
other approved resolver actions
```

GM retains authority to make direct corrective adjustments through GM tools.

All ordinary server writes must enforce:

```text
0 <= Current HP <= Final Max HP
0 <= Current MP <= Final Max MP
```

HP additionally follows the existing Down / Dying rules when it reaches 0.

---

# 6. HP Recovery

There is no free automatic HP regeneration each combat turn.

Ordinary combat healing requires an Ability, Item, treatment or another approved effect.

## 6.1 Short Rest — HP

```text
Only outside combat
Duration = 2 rounds
Recovery = ceil(Final Max HP × 10%)
```

Recovery is granted once when the required rest duration completes.

## 6.2 Long Rest — HP

```text
Only outside combat
Duration = 5 rounds
Recovery = ceil(Final Max HP × 50%)
```

Recovery is granted once when the required rest duration completes.

HP does not automatically become full from one Long Rest.

A Character at `Current HP = 0` / Down / Dying cannot use ordinary rest recovery to revive themselves. They must first be legally restored above 0 HP through treatment, healing, an Ability, an Item or another approved effect.

---

# 7. MP Recovery

Existing Canonical MP recovery remains:

## 7.1 Focus / 集中

```text
Combat only
Consumes the Character's main action
Recovery = ceil(Final Max MP × 5%)
```

Focus is not available outside combat.

## 7.2 Short Rest — MP

```text
Only outside combat
Duration = 2 rounds
Recovery = ceil(Final Max MP × 25%)
```

## 7.3 Long Rest — MP

```text
Only outside combat
Duration = 5 rounds
Recovery = Current MP to Final Max MP
```

---

# 8. Rest Chooses One Resource

A single rest does **not** restore HP and MP simultaneously.

When starting a Short Rest or Long Rest, the Character chooses one target resource:

```text
Short Rest — HP
or
Short Rest — MP

Long Rest — HP
or
Long Rest — MP
```

The selected resource is fixed for that rest instance.

---

# 9. Rest Lifecycle

Rest is individual per Character.

Characters may perform repeated rests; there is no Alpha-wide one-rest-per-encounter limit or cooldown.

The round in which rest is declared counts as the first required round.

Recovery is granted only on completion, not incrementally each round.

If combat begins before completion:

```text
Rest cancelled
No recovery granted
A new full rest must be started later
```

While a Character is resting, that Character does not use their normal Action or Move for another Character action.

The Player may still use passive/trivial interface functions, talk/chat, inspect information and perform actions unrelated to making the resting Character act.

---

# 10. Normal / Non-Combat Round Lifecycle

Outside combat, the game still uses rounds whenever action sequencing matters.

Each eligible Character receives per normal round:

```text
1 Action
1 Move
```

Normal rounds are not forced into combat DEX initiative order.

After every eligible Character has completed their Action/Move opportunity for that round, or has no Character action because they are resting/otherwise unable to act, the system advances the round.

```text
All Characters resolved
→ Round +1
→ next normal round
```

Rest progress and other round-based effects can therefore share the same round lifecycle outside combat.

---

# 11. Combat Round / Initiative Lifecycle

Combat uses the full DEX-based turn order already established by the combat rules.

```text
Start Combat
→ order combatants by DEX, high to low
→ every eligible combatant receives a turn
→ each turn provides the normal Action + Move allowance
→ after all combatants resolve their turns
→ Combat Round +1
```

Alpha does not use an additional initiative roll unless a later rule explicitly overrides this.

## 11.1 Control authority

```text
GM
→ Start Combat
→ End Combat
→ override / force progression when needed

Player
→ End Own Turn
```

Players do not start or end the global combat state themselves under the normal flow.

---

# 12. HP 0 / Down Baseline

```text
Current HP cannot be negative
Current HP = 0
→ Down / Dying state according to the existing Dying rules
```

A Down/Dying Character cannot use Focus, Rest or ordinary Character actions unless a specific Profile explicitly permits an exception.

---

# 13. Existing Data Migration

## 13.1 Existing Level-only Characters

Where existing Alpha data has a Character Level but no authoritative EXP:

```text
Existing Level L
→ EXP = minimum EXP threshold for Level L
→ Level remains L after resolver verification
```

## 13.2 Existing HP / MP data

If a Character has sufficient Canonical Attributes (`CON`, `SIZ`, `INT`) to derive HP/MP:

```text
Recalculate Canonical Max HP / MP
Apply approved modifiers
Clamp Current values to new Max values
```

If required Attributes are missing, the Character requires migration handling rather than silently trusting an arbitrary legacy Max value.

---

# 14. Persistent Storage and Legacy GM Store

Cloudflare D1 is the sole authoritative persistent game-data source for the current Alpha.

The old GM browser/local Store is deprecated for authoritative campaign data and should be removed from the production gameplay path rather than kept as a second source of truth.

Alpha test data stored only in the old GM browser Store does not require long-term dual-write compatibility.

---

# 15. GM Authentication

GM uses the same server-side User/session system as Players.

Authorization is role-based, for example:

```text
users.role = player
users.role = gm
users.role = admin
```

GM permissions are enforced server-side from the authenticated User role.

A separate unrelated GM-password persistence system is not the Alpha direction.

---

# 16. Alpha Implementation Requirement

A rule is not considered implemented merely because it exists in Markdown.

For the active Alpha build, confirmed Canonical rules must be reflected in the relevant production path:

```text
D1 schema/data model
Worker/server resolver
GM controls
Player controls
round / combat state
resource actions
validation / audit history
```

Documentation remains the Canonical specification; the Alpha build must execute the same rules.

# 17. Locked Decision Summary

1. Level-up Max-resource gains also increase Current HP/MP by the same delta.
2. EXP continues accumulating after Level 100 while Level remains capped at 100.
3. GM can add/subtract EXP and set Total EXP.
4. GM Starting Level converts to that Level's minimum EXP threshold.
5. Character creation uses system roll + Player reroll + Player confirmation.
6. Permanent Attribute-driven Max increases also add the same delta to Current resources.
7. Max HP/MP use Canonical formula + explicit modifier; GM may edit the modifier value.
8. Player cannot arbitrarily type Current HP/MP; gameplay/system resolvers handle ordinary resource changes, with GM corrective authority.
9. Each Rest chooses HP or MP, not both.
10. Rest may be repeated.
11. Resting Character cannot take normal Character Action/Move; Player may still chat and use unrelated/passive UI functions.
12. Rest is individual per Character.
13. Outside combat every eligible Character has 1 Action + 1 Move; after all Characters resolve, the round advances.
14. Combat uses full DEX-based turn order so every eligible combatant acts.
15. GM starts/ends combat; Player ends their own turn; GM may override.
16. Focus is combat-only.
17. HP floors at 0 and 0 enters Down/Dying handling.
18. Legacy Level migrates to the minimum EXP threshold for that Level.
19. Legacy HP/MP recalculates from Canonical Attributes when available; missing required Attributes need migration handling.
20. Old GM browser Store is not retained as a second authoritative source.
21. GM authentication uses the same User/session system with role-based authorization.
