# 對抗判定與極端結果 — Alpha

> 狀態：Canonical Alpha Working Rule  
> 範圍：對抗判定、平手、命中與效果分離、大成功／大失敗、GM + AI 情境推演。  
> 本文件與 `D100判定核心_ALPHA.md` 一起使用；若較早 Combat 文件仍使用舊式 `Skill + Source Bonus` 作獨立命中公式，本文件與最新 D100 核心優先。

---

# 1. 核心原則：機械結果 ≠ 故事好壞

D100 的結果首先描述：

```text
角色把自己想做的事情做得有多好／多差
```

而不是直接描述：

```text
這件事最後對玩家有多有利／多不利
```

因此：

```text
大成功 ≠ 一定得到好結果
大失敗 ≠ 一定只是「甚麼也沒有發生」
```

故事後果必須再考慮：

- 行動原意；
- 能力／物品本身的效果；
- 目標；
- 周圍角色；
- 地形與環境；
- 物件材質／結構；
- 當前 Buff／Debuff／狀態；
- 已存在的 Damage Profile／Ability Profile；
- 前一個事件留下的狀態；
- 合理的因果鏈。

---

# 2. 對抗判定沿用同一 D100 Result

雙方都使用最新 D100 核心公式：

```text
Result = 骰點 - [100 - (技能值 + 總修正)]
```

不建立另一套「對抗專用骰法」。

一般競爭型對抗：

```text
A Result > B Result
→ A 在該次對抗勝出

A Result < B Result
→ B 在該次對抗勝出

A Result = B Result
→ 互相抵消
→ 維持現狀／防守方優先
```

平手不需要再加骰或使用隱藏 Tie Breaker。

---

# 3. 完全相同 = 互相抵消

Canonical：

```text
完全相同的對抗 Result
→ 互相抵消
```

例如：

```text
A 攻擊 Result = +32
B 閃避 Result = +32

→ 攻擊未能壓過閃避
→ 視為沒有命中
```

這代表主動一方必須「嚴格高於」對抗方，才可以突破對方的反應／防守。

這個原則亦可用於：

```text
潛行 vs 察覺
欺瞞 vs 洞察
擒抱 vs 反抗
推撞 vs 穩定
法術控制 vs 抵抗
其他真正的競爭型判定
```

具體敘事由 GM 按情境描述，但機械上平手不給主動方額外優勢。

---

# 4. 「命中」與「有效造成效果」可以分離

某些行動只需要一次對抗；但某些戰鬥／能力可以有兩個不同問題：

```text
第一層：有沒有接觸／命中？
第二層：命中後有沒有突破防禦／造成有效效果？
```

因此允許出現：

```text
攻擊成功命中
但
攻擊效果不足以突破對方防禦

→ 命中，但無效／被防住／沒有造成實質傷害
```

例如：

```text
命中判定：攻擊 Result > 閃避 Result
→ 打中

之後效果／威力 < 對方有效防禦
→ 攻擊接觸目標，但沒有造成有效傷害
```

注意：

- 不是所有行動都強制兩階段；
- 是否需要第二層由該 Ability／Damage Profile／防禦系統決定；
- 目前不在本文件鎖死「攻擊威力 vs 防禦」的數值公式；
- 這裡只鎖定「命中不等於一定造成效果」的架構。

# 5. 大成功／大失敗不使用固定後果表

原始 D100：

```text
1   = 大失敗
100 = 大成功
```

但不建立例如：

```text
大成功 = 傷害 ×2
大失敗 = 必定打隊友
```

這類全域固定規則。

原因：同一個極端骰面，在不同能力、環境與故事情況下，合理後果可以完全不同。

因此大成功／大失敗進入：

```text
極端結果情境推演
```

由 GM 作最終裁決，AI 可以協助提出合理因果與後果。

---

# 6. 大成功：效果超額完成，但不保證安全

大成功首先代表：

```text
角色嘗試做的事情
→ 被極高程度地實現／放大／超額完成
```

它不是「幸運獎勵」的同義詞。

例如：

```text
行動：召喚水
普通成功：召出足夠使用的一股水

大成功：召水效果被大幅放大
→ 可能形成池塘級、甚至接近湖量級的大量水體
```

若角色在安全的野外：

```text
大量水
→ 可能是非常有利的大成功
```

若角色在密閉房間：

```text
大量水
→ 房間迅速被淹
→ 角色、隊友、敵人、物件一同受影響
→ 後續可能出現溺水、漂浮、門窗受壓、電氣危險等連鎖事件
```

所以：

```text
機械上：大成功
故事上：可能非常麻煩
```

兩者完全可以同時成立。

---

# 7. 大失敗：行動嚴重偏離，可能產生次生事件

普通失敗通常可以很簡單：

```text
想打敵人
→ 沒打中
→ 行動結束
```

大失敗則允許 GM／AI考慮：

```text
攻擊沒有命中原目標
而且
力量／投射物／魔法／物件仍然去了其他地方
```

例如：

```text
大失敗攻擊
→ 偏離原目標
```

可能合理地導致：

```text
打中隊友
打中牆壁／地板
打碎附近物件
武器卡住／脫手
擊中承重結構
觸發陷阱
擊穿管線／容器
引發火災／漏水／坍塌
驚動其他敵人
```

但以上全部只是可能性，不是固定表。

---

# 8. 連鎖反應由世界狀態推演，不憑空生成

如果大失敗打中地板，不能自動寫成：

```text
打中地板
→ 地板一定穿洞
```

系統／GM／AI 必須再考慮：

```text
這次攻擊的實際威力
地板材質
地板厚度／結構
既有損傷
攻擊類型
是否有爆炸／穿透／震盪
周圍環境
```

只有合理時才會：

```text
地板破裂／穿洞
↓
角色掉落
↓
下層物件被擊中
↓
形成新的事件鏈
```

因此極端結果的核心不是「隨機加懲罰／獎勵」，而是：

```text
極端輸出
+ 當前世界狀態
→ 合理因果
→ 可能產生後續事件
```

# 9. GM + AI 的角色分工

AI 可以在大成功／大失敗或其他高歧義極端事件時協助 GM 推演。

AI 應收到：

```text
角色原本想做甚麼
原始骰點
最終 Result
技能／Ability／Damage Profile
效果規模
目標
附近角色
環境／地形
相關物件與材質
已存在的狀態／Buff／Debuff
```

AI 回傳的重點不是固定「獎勵／懲罰」，而是：

```text
建議的直接結果
可能的次生結果
必要時的連鎖反應
簡短因果說明
```

GM 最終可以：

```text
接受
修改
拒絕
```

AI 不得自行成為最終裁決者。

---

# 10. 極端結果不必標準化成單一強度公式

目前不鎖死：

```text
大成功一定放大多少倍
大失敗一定偏離多少格
大成功一定增加多少傷害
大失敗一定造成多少額外傷害
```

不同能力應按本身 Scale／Profile 及故事環境處理。

因此：

```text
100
→ 觸發「大成功」解讀
→ 由能力效果 + 環境 + GM/AI 合理化

1
→ 觸發「大失敗」解讀
→ 由行動偏離 + 環境 + GM/AI 合理化
```

這避免一個固定表硬套在攻擊、治療、召喚、移動、社交、製作、探索等完全不同的行動上。

---

# 11. 與技能成長的關係

基礎技能的使用成長仍沿用既有規則：

```text
有效 D100 判定出現大成功
→ 有資格獲得該技能的大成功成長進度
```

即使大成功因環境造成不利的故事後果，它仍然是一次「極端成功地執行／放大該行動」的結果，因此不因後續故事麻煩而自動失去大成功標記。

實際成長進度仍依既有 Alpha 規則處理。

---

# 12. Alpha 鎖定結論

1. 對抗雙方沿用同一 D100 Result，不建立第二套骰法。
2. 競爭型對抗比較 Result；數值較高者勝。
3. Result 完全相同時互相抵消，維持現狀／防守方優先。
4. 攻擊 Result 與閃避 Result 相同時，視為未命中。
5. 命中與造成有效效果可以是兩個不同階段；命中不保證突破防禦。
6. 原始 1 為大失敗；原始 100 為大成功。
7. 大成功／大失敗不使用全域固定後果表。
8. 大成功代表行動效果可能被極高程度實現／放大，但故事後果不一定對玩家有利。
9. 大失敗代表行動嚴重偏離原意，可能因世界狀態產生合理的次生／連鎖事件。
10. 連鎖反應必須基於實際能力威力、環境、物件與既有狀態，不得憑空生成。
11. AI 可提供情境推演與因果解釋；GM 是最終裁決者。
12. 大成功即使造成不利連鎖後果，仍可依既有規則觸發基礎技能的大成功成長進度。
